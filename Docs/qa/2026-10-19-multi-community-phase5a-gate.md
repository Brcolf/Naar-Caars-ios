## PR Impact Summary (Phase 5a)

**What changes for people using the app: nothing visible.** No screen is added or redesigned, and no string key is added (75 keys become unused and stay in the catalog until an owner-approved cleanup). Only two things change behind the screens: where image and voice-note bytes are downloaded from, and which endpoint the ride-cost estimate calls for its place lookup.

1. **Removed screens and services**, all unreachable (table above): the legacy invite-code UI and service, the signup-method choice, the platform Pending Users screens, the application form, the debug view, the legacy `Log` enum and the dead Rides and Favors dashboards (21 files, every project reference gone, `PBXCHECK` clean).
2. **No client writes `profiles.heard_about`, `join_reason`, `application_complete` or `approved`, and none calls `admin_reject_pending_user`.** Answers reach `community_members` only through the community RPCs. The server's own copy of the answers into `profiles` (default community) remains until File B (D-9), because the installed build's admin screen reads it.
3. **Ride-cost place lookups go through two definer RPCs** (`get_geocoding_multiplier`, `put_geocoding_multiplier`; File A, live). They require an active account, validate the key, the coordinates and the multiplier range, and return or store only the multiplier. A cache row is fresh for 24 hours from its last write (`updated_at`). No placemark data is sent, and the 7 stored placemarks were cleared. A missing function (`PGRST202` / `42883`) turns the lookup off for the session; any other error leaves it on. The estimate itself still comes from the on-device rules.
4. **Images in `message-images`, `group-images`, `town-hall-images` and `review-images`, and voice notes in `audio-messages` (D-1, accepted), download through signed URLs** (`StorageURLSigner`: 1-hour lifetime, renewed 5 minutes before expiry, one request per object for concurrent resolves, at most 500 entries, in memory only, reset at sign-out). Downloads use `URLSession.signedStorageDownload` (ephemeral, no `URLCache`). The disk image cache and the audio temp files stay keyed by the stored URL. **What is stored does not change**: `messages.image_url` / `audio_url`, `conversations.group_image_url`, `town_hall_posts.image_url`, `reviews.image_url`, `SDMessage` and `SDTownHallPost` keep the public URL the upload returned (D-2), so the installed build keeps showing new media until File E. While the buckets are public, a signing failure falls back to the stored URL. A voice-note download that is not a 2xx answer is neither written nor cached (`61ef090`). Avatars stay public.
5. **Nothing in 5b is applied**: see "5b: NOT APPLIED" above. Files B-E wait for A5 point 2 (no pre-community build in use). Files D and E also wait until every build in use contains this client.

**Coordinator, realtime, send path.** `RefreshCoordinator`, `RealtimeManager`, `MessageSendManager`, `MessageSendWorker`, `MessagingRepository`, `BackgroundSyncActor`, `SDModels`, the mappers, `NavigationCoordinator`, `PushNotificationService`, `BadgeCountManager` and the notification registry are unchanged. No coordinator call is added. `MessagingSyncEngine` changes only in its private voice-note prefetch (above).

**High-blast-radius files touched, and what breaks if a consumer is missed**

| File | Change | If a consumer were missed |
|---|---|---|
| `AuthService` | Dead invite-code sign-up methods removed; `clearPerAccountLocalState` gains `await StorageURLSigner.shared.reset()` | A caller of a removed method stops compiling (none existed; the build and the full suite are green). Without the reset, the next account on the device would reuse signed URLs issued to the previous one until they expire. |
| `PersistentImageService` | Disk cache first; on a miss, resolve through `urlResolver` and download through `signedStorageDownload`; logs only domain and code | Every remote image in the app goes through `getImage(for:)` (`CachedAsyncImage`, `ImageBubbleView`, `AvatarUIView`, `ImageViewerView`). A path that downloaded through `URLSession.shared` would write a token-bearing URL into `URLCache`'s disk store. Once File E applies, a path that skipped the resolver would show a broken image. |
| `MessageAudioPlayer` / `MessagingSyncEngine` | Voice notes resolve and download the same way; the receive-path prefetch fills the player's temp-file cache through `VoiceNotePrefetching` | A prefetch that still warmed `URLCache.shared` would store the signed URL on disk. A player path without the resolver would leave voice notes unplayable after File E. |
| `AdminService` | `fetchPendingUsers`, `approveUser`, `rejectUser` removed (not on the protocol) | A screen still calling them stops compiling. The `.pendingUsers` route already opens Requests to join. `EmailService.sendWelcomeEmail` lost its only caller (follow-up). |
| `ProfileService` / `ProfileServiceProtocol` | `submitApplication`, `fetchInviteCodes`, `generateInviteCode` removed | A test stub or conformer that still declared them would be harmless; a caller would stop compiling. |
| `GeocodingCacheService` / `RideCostEstimator` | Table calls replaced by the two RPCs; `cleanupGeocodingCache` and the placemark payload removed | Against a server without File A, the lookup turns off for the session and estimates still come out. File A is live (step 1). Once File D applies, a remaining direct table call would fail with `42501`. |
| `Constants` | `Storage.signedURLLifetime`, `signedURLRenewMargin`, `signedURLCacheMaxEntries` | None outside the signer and its tests. |
| `StorageURLSigner.signedBuckets` | Four image buckets plus `audio-messages` | A bucket that File E makes private but is left out here would stop loading for this build once File E applies. |
