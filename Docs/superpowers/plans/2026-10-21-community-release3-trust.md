# Community Release 3 (trust) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The client half of Release 3: read requests through the member views, draw areas as circles and addresses only when the server says they are shared, offer to help in open communities with the poster choosing on an Offers card, answer questions on the request, close request threads, narrow New Message to reachable people, show the 24-hour cool-off, open communities once the server allows them, and route the four new notification types.

**Architecture:** `SupabaseService.ridesReadSource` / `favorsReadSource` move to `member_rides` / `member_favors`; `Ride` and `Favor` gain flat optional area, point and offer fields that the SwiftData trio stores additively, and one pure builder (`RequestPlace.make`) decides address, area or hidden for every screen. All help actions go through `ClaimService` on the new definer RPCs (`help_with_request`, `withdraw_help`, `get_request_offers`, `accept_request_offer`, `decline_request_offer`, `release_helper`); two new `ObservableObject` ViewModels own the helper's offer sheet and the poster's Offers card and reload only through the sanctioned `forceFullRefreshAndWait` triggers. The UIKit messaging path is untouched except the existing frozen state, which also covers a closed request thread; open communities and the "only then are addresses shared" sentences follow the server switch `get_trust_features()`, so the build behaves correctly before and after the 3b flip.

**Tech Stack:** Swift 6.3 toolchain in Swift 5 mode, SwiftUI (MapKit `MapCircle`, `Marker`), UIKit messaging (unchanged), SwiftData, XCTest, Xcode 26.6 / iOS 26.5 SDK, supabase-swift.

**Spec:** `Docs/superpowers/specs/2026-10-21-community-discovery-and-trust-design.md` (4.4-4.8, the Release 3 paragraph of 4.10; mockups S2, S4, S5, S6 under `build/design/mockups/navigation-mockups.html`, where 4.9 lists what differs). The server contract is `Docs/superpowers/plans/2026-10-21-community-release3-trust-sql.md` ("Interfaces the iOS plan relies on"). It builds on Release 1 (`2026-10-21-community-release1-navigation.md`) and Release 2 (`2026-10-21-community-release2-discovery.md`).

## Global Constraints

- `IPHONEOS_DEPLOYMENT_TARGET = 26.0`, `SWIFT_VERSION = 5.0`, `SWIFT_APPROACHABLE_CONCURRENCY = YES`, `SWIFT_DEFAULT_ACTOR_ISOLATION = nonisolated`. No build setting, permission, entitlement, Info.plist key or SDK change (the location permission is Release 2's).
- **The server decides.** Screens never decide who sees an address, may offer, message, post or ask; they show what `addresses_shared`, `help_mode`, the RPC refusal codes and the `NC00x` errors say (spec 3).
- **No phone appears anywhere** (spec 4.6). The phone on file stays a precondition the server checks (`phone_required`).
- **Spec 4.4, verbatim:** "Cards, detail screens and `RequestMapView` draw circles from the area columns and pins from exact coordinates, with no on-device geocoding of other people's addresses; Copy and Open in Maps need `addresses_shared`." So pins come only from exact coordinates, circles only from area centers, Copy and Open in Maps only for `RequestPlace.address` (Open in Maps passes the coordinate, else the address text, and never geocodes on the device); the one geocoding path left is the poster's own request without exact points (Task 5, decision 9).
- **RefreshCoordinator.** ViewModels call only `forceFullRefreshAndWait`. Sanctioned triggers added by this release: `.dashboard` `userAction:helpWithRequest` and `userAction:withdrawHelp` (through `RequestsDashboardRefresh.afterUserAction`), `.dashboard` and `.badges` `offerDecision` (accept, decline, release, from `RequestOffersViewModel`), and the existing `.dashboard` `joinedCommunity` after an open join. No new domain, timer or `refreshIfNeeded` call; offers ride on `.dashboard` and `.badges`.
- **UIKit messaging untouched** except the closed state through the existing `isConversationFrozen` path (`setComposerSuppressed`); `git diff --stat <R3 base>..HEAD -- NaarsCars/Features/Messaging/Views/MessagesViewController.swift NaarsCars/UI/Components/Messaging/MessagesCollectionView.swift NaarsCars/Features/Messaging/ViewModels/MessageSendManager.swift NaarsCars/Core/Services/MessageSendWorker.swift NaarsCars/Core/Services/RealtimeManager.swift NaarsCars/Core/Services/RefreshCoordinator.swift` is empty at the gate.
